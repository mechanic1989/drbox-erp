처음 올릴 때는 ①→②→③→④ 순서로, 이미 v2.1~v2.3을 쓰고 있다면 ②의 "업데이트" 부분만 보면 됩니다.

① 파일 설명 (압축을 풀면 나오는 것)
──────────────────────────────────────────────
  upload_to_github/             ← 이 폴더 안의 6개 파일을 GitHub 저장소(drbox-erp) 맨 위(루트)에 올립니다 (폴더째 말고 파일들만)
    index.html                  앱 본체 (= BoxERP_app_same_as_index.html 과 같은 파일, 이름만 index.html). 약 1.1MB
    manifest.json               앱 이름·아이콘·시작 화면 정보 (홈 화면 설치용)
    sw.js                       오프라인 캐시(서비스워커). 이번 버전은 'box-erp-v20'
    icon-192.png / icon-512.png / icon-512-maskable.png   홈 화면 아이콘
  firebase_rules.json           ← GitHub가 아니라 Firebase 콘솔 "규칙" 탭에 붙여넣는 보안 규칙 (③ 참고)
  BoxERP_app_same_as_index.html ← index.html 과 내용이 같습니다. PC에서 더블클릭해 로컬로만 써보거나, 앱 파일 자체를 보관해 둘 때
  README.txt                    이 문서
  ※ 폴더·파일 이름을 영문으로 한 이유: 압축 파일 안의 한글 이름은 윈도우 기본 압축 해제 시 깨지거나 빠질 수 있어서입니다.

  ※ 앱은 파일 하나(index.html)에 전부 들어 있습니다. 서버 설치나 별도 프로그램은 필요 없습니다.
  ※ 데이터는 index.html 안에 들어 있지 않습니다. 각 기기(IndexedDB)와 Firebase 클라우드에 저장되므로
     index.html 을 새 버전으로 바꿔 올려도 데이터는 그대로입니다.

② GitHub에 올리기 (GitHub Pages)
──────────────────────────────────────────────
[처음 올리는 경우]
  1. https://github.com 로그인 (계정: mechanic1989) → 오른쪽 위 "+" → "New repository"
     · Repository name: drbox-erp   · Public 선택   · "Add a README file" 체크   → Create repository
  2. 저장소 화면에서 "Add file" → "Upload files"
     · 압축 푼 "upload_to_github" 폴더 안의 파일 6개를 창에 끌어다 놓기 (폴더째가 아니라 파일들만!)
     · 아래 "Commit changes" 버튼 클릭 → 잠시 후 파일 목록에 6개가 보이면 됨
  3. 저장소 "Settings" 탭 → 왼쪽 메뉴 "Pages"
     · Source: "Deploy from a branch"   · Branch: main  /  (root)  → Save
     · 1~3분 뒤 같은 화면 위쪽에 주소가 뜹니다:  https://mechanic1989.github.io/drbox-erp/
  4. 그 주소를 크롬에서 열어 로그인 화면이 보이면 성공. (③ Firebase 설정을 마쳐야 Google 로그인이 됩니다)

[이미 사용 중 → v2.4 로 업데이트]
  1. GitHub → drbox-erp 저장소 → "Add file" → "Upload files" → "upload_to_github" 폴더의 6개 파일을 끌어다 놓기
     (같은 이름의 파일은 자동으로 새 것으로 바뀝니다) → "Commit changes"
     · 예전에 박스단가계산기.html 이름으로 올려 쓰고 있었다면: index.html 을 올리고, 옛 파일은 저장소에서
       파일 클릭 → 오른쪽 위 "…" → Delete file 로 지워도 되고 그대로 두어도 됩니다 (주소는 /drbox-erp/ 로 통일 권장).
  2. 1~3분 기다린 뒤, 사용 중인 모든 기기에서 앱을 새로고침 2번 (첫 번째 새로고침은 새 파일 받기, 두 번째는 적용)
     · PC 크롬: F5 두 번  · 폰: 화면 당겨서 새로고침 두 번, 또는 앱을 완전히 닫았다 다시 열기
  3. 헤더의 빨간 배지가 v2.4.12 로 바뀌었는지 확인. 안 바뀌면 한 번 더 새로고침하거나 브라우저를 완전히 종료 후 재실행.
  4. 이제부터는 저장 뒤 3분 안에 자동으로 백업이 됩니다 (⑥). 헤더의 "☁️ 백업됨 · n분 전" 표시로 확인하세요.

  ※ 앞으로 앱을 수정해 다시 올릴 때는 sw.js 의 VERSION 을 'box-erp-v6', 'v7' … 로 올려서 함께 올리면
     모든 기기가 새 버전을 확실히 받습니다. (이번 v2.4.12 는 v20 으로 되어 있으므로 그대로 올리면 됩니다)

③ Firebase 콘솔 설정 (처음 1회 · 이미 했다면 "규칙"만 확인)
──────────────────────────────────────────────
  https://console.firebase.google.com → 프로젝트 drbox-a1fe7
  A. Google 로그인 허용
     · 왼쪽 "빌드" → "Authentication" → "Sign-in method" 탭 → Google 이 "사용 설정됨" 인지 확인 (아니면 켜고 저장)
     · "Settings" 탭 → "승인된 도메인(Authorized domains)" 에 mechanic1989.github.io 가 있어야 합니다. 없으면 "도메인 추가".
       → 이것이 빠지면 로그인 창이 떴다가 "auth/unauthorized-domain" 오류로 닫힙니다.
  B. 데이터베이스 규칙 (팀 공유·자동 백업 저장에 필요)
     · "빌드" → "Realtime Database" → "규칙" 탭 → 기존 내용을 모두 지우고 firebase_rules.json 내용을 붙여넣기 → "게시"
     · 앱 안에서도 복사할 수 있습니다: 헤더 👥(팀) 버튼 → "⚙️ 최초 1회 설정" → "📋 규칙 복사"
     · 규칙 요약: 본인 데이터는 본인만, 팀원은 초대받은 워크스페이스만 읽고(뷰어) / 쓰기(편집자·관리자). 백업(backups2)도 같은 규칙.
  C. 확인
     · 앱 주소에서 Google 로그인 → 헤더에 이름이 뜨고, 잠시 뒤 "☁️ 백업됨" 이 보이면 정상.
     · "⚠️ 동기화 실패" 또는 "⚠️ 클라우드 백업 실패" 가 뜨면 B의 규칙이 게시되지 않은 것입니다.

④ 첫 실행 · 데이터 이전
──────────────────────────────────────────────
  · Google 로그인 → 이전 버전 데이터가 있으면 새 구조(레코드 단위)로 자동 이전됩니다. 몇 초~수십 초 걸릴 수 있고
    이전 중에는 헤더에 "동기화 준비 중…" 이 표시됩니다. 원래 데이터는 클라우드에 그대로 남습니다.
  · v2.3 이후 기기 저장소는 IndexedDB 입니다. 예전 localStorage 데이터는 첫 실행 때 자동으로 옮깁니다 (5MB 제한 해제).
  · 모든 기기를 v2.4 로 올린 뒤 사용하세요. 구버전(v2.1 이하)이 남아 있으면 그 기기의 변경이 새 구조에 반영되지 않습니다.
  · 웹 주소(https://mechanic1989.github.io/drbox-erp/)에서는 Google 로그인만 사용합니다. "로컬 모드" 버튼은 HTML 파일을
    더블클릭해 직접 열었을 때만 나타나며, 로컬 모드 데이터는 그 브라우저에만 저장되고 클라우드와 공유되지 않습니다.
    (로컬 모드로 만든 데이터를 계정으로 옮기려면: 로컬 모드 화면에서 💾 백업 → 로그인 화면에서 📂 복원 → 백업 파일에서 복원)
  · 한 번 로그인해 두면 인터넷이 잠시 끊겨도 앱이 열리고 저장되며, 연결되면 클라우드에 반영·백업됩니다.

  · 설치된 앱은 sw.js 덕분에 인터넷이 잠깐 끊겨도 열립니다. (데이터 저장은 되고, 연결되면 클라우드에 반영·백업)
  · 현품표 인쇄 시 우하단 QR(수주번호) → 폰 카메라로 찍으면 해당 수주의 출고 화면이 열립니다.
    앱 안에서는 납기관리 → "📷 QR 출고" (카메라는 https 주소에서만 동작).

⑥ 자동 백업 — 어떻게 동작하나 (v2.4 핵심)
──────────────────────────────────────────────
  [언제]
    · 무엇이든 저장하면 "변경됨" 상태가 되고, 입력이 멈춘 뒤 3분 지나면 스냅샷을 만듭니다.
    · 계속 입력 중이어도 최대 15분마다 한 번은 만듭니다.
    · 앱을 벗어나면(탭 숨김·다른 앱으로 전환·창 최소화) 기다리지 않고 즉시 만듭니다.
    · 앱을 켤 때와 1시간마다 "빠진 변경이 있는지" 점검합니다. 내용이 같으면(해시 비교) 저장하지 않습니다.
    · 다른 기기·팀원이 바꾼 내용도 켜져 있는 기기가 백업합니다. 여러 기기가 켜져 있어도 같은 내용은 한 번만 올라갑니다.
  [어디에]
    · 이 기기: 브라우저 IndexedDB (📂 "이 기기의 스냅샷")  — 최근 10개 + 하루 1개×7일
    · 클라우드: Firebase users/(계정)/backups2  (📂 "클라우드 스냅샷") — 최근 24개 + 하루 1개×30일 + 한 달 1개×12개월
    · gzip 압축으로 저장합니다 (수주 4,000건 기준 5.2MB → 1.0MB). 1회 백업에 화면이 멈추는 시간은 약 0.05초.
  [긴급 보관 (📌)]
    · 엑셀 교체 등으로 200건 넘게 한 번에 삭제되기 직전, 그리고 복원 직전 상태는 별도로 7일간 보관합니다.
  [상태 표시]  헤더(PC) 또는 ☰ 메뉴 맨 위(폰)
    · ☁️ 백업됨 · 3분 전     정상 (로컬 모드는 💾)
    · ⏳ 변경됨 · 2분 후 백업  저장한 내용이 있고 곧 백업 예정
    · ⏫ 백업 중…            저장 중
    · 📴 오프라인             인터넷 끊김. 연결되면 자동으로 백업
    · ⚠️ 클라우드 백업 실패   2분→4분→…최대 30분 간격으로 자동 재시도. 계속되면 ③-B 규칙 확인
    · 클릭하면 📂 백업·복원 창이 열립니다.
  [설정]  📂 백업·복원 → "⚙️ 자동 백업 설정"
    · 유휴 대기(1~10분) · 최대 간격(5~60분) · 클라우드 백업 켜기/끄기 · 이 기기 스냅샷 켜기/끄기
    · "주 1회 백업 파일 자동 다운로드(PC)": 켜 두면 PC에서 앱을 열 때 마지막 파일 백업이 7일 넘었으면
      박스ERP_백업_날짜.json 을 다운로드 폴더에 자동 저장합니다. → 이 파일을 USB나 구글드라이브에 옮겨 두면 완전한 3중 백업.
  [파일 백업]  헤더 💾 백업 (또는 📂 → "파일로 내려받기")
    · 인쇄사양서 이미지까지 포함한 전체 백업 파일(.json). 자동 스냅샷은 용량 때문에 이미지를 뺍니다.
    · 홈 화면에 "마지막 파일 백업이 n일 전" 알림이 뜹니다. 월 1회 이상 권장.

⑦ 문제가 생겼을 때 — 복구 방법
──────────────────────────────────────────────
  A. 레코드 하나를 잘못 고쳤다 / 잘못 지웠다 / 잘못 추가했다
     → 헤더 🕘 이력 → 해당 줄의 "↩ 이전 상태로" / "↩ 복원" / "↩ 추가 취소" 클릭. 그 한 건만 되돌아갑니다.
     → 삭제 직후라면 화면 우하단 토스트의 "↩ 되돌리기", 또는 🕘 이력 → 🗑 휴지통에서도 복원됩니다.
  B. 엑셀을 잘못 올려서 목록 전체가 바뀌었다 / 여러 건이 한꺼번에 잘못됐다
     → 📂 백업·복원 → "이 기기의 스냅샷" 맨 위의 📌 "일괄삭제 전 자동보관" 또는 그 직전 시각의 스냅샷 → 복원
     → 복원은 모든 데이터를 그 시점으로 되돌립니다. 복원 직전 상태도 "복원 전 자동보관" 으로 남으니 다시 되돌릴 수 있습니다.
     → 확인 창 → "복원 완료" → 자동 새로고침. 로그인 상태면 클라우드도 함께 그 시점으로 바뀝니다 (팀원 화면도 동일).
  C. 기기를 잃어버렸다 / 브라우저 데이터를 지웠다 / 새 PC
     → 새 기기에서 주소 열고 같은 Google 계정으로 로그인 → 클라우드 데이터가 그대로 내려옵니다.
     → 클라우드까지 잘못됐다면 📂 → "클라우드 스냅샷" 에서 시각을 골라 복원.
  D. 인터넷이 끊긴 채로 입력하다가 앱을 닫았다
     → 그 기기에서 다시 열면 "지난번 저장되지 않았던 변경 n건을 클라우드와 병합했습니다" 안내가 뜨고 자동으로 합쳐집니다
       (같은 레코드를 양쪽에서 고쳤으면 나중에 고친 쪽이 남습니다). 🕘 이력에 "병합" 으로 기록됩니다.
     → 아직 클라우드에 안 올라간 변경이 있는 상태에서 창을 닫으려 하면 브라우저가 경고합니다. 잠시 후 다시 시도하세요.
  E. "데이터가 손상되어 읽을 수 없습니다" 경고가 떴다
     → 매우 드문 경우입니다(기기 저장소 파손). 원문은 "손상 데이터 원문 보관" 스냅샷으로 남고, 📂 에서 직전 스냅샷을 복원하면 됩니다.
  F. 백업 파일(.json)로 복원
     → 📂 → "백업 파일(.json)에서 복원" → 파일 선택 → 확인. v2.1 이후 어떤 버전의 백업 파일도 복원됩니다.
  G. 로그인이 안 된다
     → ③-A 승인된 도메인 확인 / 팝업 차단 해제.
     → 폰 브라우저(삼성 인터넷 등)에서 로그인을 눌러도 다시 로그인 화면으로 돌아오면: 브라우저 추적 방지 때문에 로그인 결과를
       못 받는 경우입니다. v2.4.2 부터는 팝업 방식으로 로그인하므로 해결되며, 그래도 안 되면 크롬 브라우저로 열거나
       삼성 인터넷 설정 → 개인정보 보호 → "스마트 추적 방지" 를 끄고 시도하세요. 카카오톡 안에서 열면 정상 동작합니다.
  H. 새 버전이 안 보인다
     → 새로고침 2번. 그래도 안 되면 브라우저 완전 종료 후 재실행, PWA 는 삭제 후 다시 설치 (데이터는 계정에 있으므로 안전).
  I. "⚠️ 기기 저장 실패" 가 뜬다
     → 저장공간이 꽉 찼거나 사생활 보호 모드입니다. 일반 창에서 열고, 📂 창 상단의 저장소 용량을 확인하세요.

       이미 그런 기록이 있으면 데이터 검진의 "같은 출고번호에 같은 수주가 두 번 들어간 출고"에 표시되고,
       수량·출고일이 같은 두 줄이면 [중복 줄 지우기]로 한 줄을 지울 수 있음 (그 밖의 경우는 ✏️ 출고 수정에서 나머지 줄의 수량을 0 으로)
     - 출고번호별 거래명세표의 날짜·단가 기준일을 그 출고의 출고일로 (부분 출고 때 가장 최근 출고일이 찍히던 것)
     - 마감된 달 날짜의 출고·입고가 ↩ 출고취소 · 출고 선택 취소 · 입고 선택 취소로 지워지던 것 → 마감된 달의 것은 남기고 열린 달의 것만 취소
     - 입고·출고 창이 떠 있는 사이 다른 기기에서 목록이 바뀌면 엉뚱한 건이 처리될 수 있던 것 → 처리하지 않고 다시 시도하라고 안내
     - 데이터 검진: 수주수량보다 많이 출고한 건을 오류로 보지 않음 (수주의 출고수량과 출고 기록 합계가 다를 때만 오류) — 대신

     - 출고수량을 모두 0으로 두고 출고처리를 누르면 아무 안내 없이 창이 닫히던 것 ·
