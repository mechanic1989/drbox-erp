 박스 ERP v2.5.1 — 업로드 · 설치 · 사용 · 백업/복원 안내 (안정성 중심)
══════════════════════════════════════════════════════════════════

이 문서는 ⓪ v2.5.1 으로 올릴 때 꼭 할 일 ① 파일 설명 ② GitHub에 올리는 순서 ③ Firebase 설정 ④ 첫 실행 ⑤ 앱 설치
⑥ 자동 백업이 어떻게 동작하는지 ⑦ 문제가 생겼을 때 복구하는 방법 ⑧ 안정 운영 수칙 ⑨ 팀 공유 ⑩ 버전별 변경 요약 순서로 되어 있습니다.
처음 올릴 때는 ①→②→③→④ 순서로, 이미 v2.4 를 쓰고 있다면 ⓪ 과 ②의 "업데이트" 부분만 보면 됩니다.

──────────────────────────────────────────────
⓪ v2.5.1 으로 올릴 때 꼭 할 일 (v2.4.x · v2.5.0 → v2.5.1)
──────────────────────────────────────────────
  ★ 이미 v2.5.0 을 쓰고 있다면: upload_to_github 폴더 안의 index.html 과 sw.js 두 파일만 GitHub 저장소 맨 바깥(index.html·sw.js 가 있는 자리)에
     덮어 올리면 끝입니다(아래 2~9 는 v2.5.0 때 이미 한 것). 1~3분 뒤 새로고침하면 배지가 v2.5.1 로 바뀝니다. sw.js 는 이번에 'box-erp-v25' 입니다.
     주의: upload_to_github 를 폴더째 올리면 앱이 바뀌지 않습니다 — 파일 6개를 맨 바깥에 두어야 합니다.
  v2.5.0 은 정밀 검토에서 나온 문제 약 150건(겹침 제외)을 한 번에 고친 큰 업데이트입니다. v2.4.x 에서 올리면 아래 순서대로 해 주세요.
  1. GitHub 에 upload_to_github 폴더의 6개 파일을 올립니다 (② 업데이트 순서 그대로). sw.js 는 이번에 'box-erp-v25' 입니다.
  2. ★ Firebase 보안 규칙을 새 firebase_rules.json 으로 다시 붙여 넣습니다 (③-B, 1회). 초대·권한 관련 취약점을 막고 로그인한 기기 기록
     (devices — 팀원은 자기 기기만, [접속 끊기]는 소유자·관리자만)을 지키는 규칙이라 붙이지 않으면 앱은 돌아가지만 보안 보강이 완성되지 않습니다. 붙인 뒤 앱을 한 번 새로고침해 "⚠️ 동기화 실패"가 없는지 확인하고,
     대표 계정으로 👥 팀 창을 열어 "⚙️ Firebase 보안 규칙" 줄에 "✅ 새 규칙 적용됨"이 나오면 끝입니다("⚠️ 아직 예전 규칙"이면 다시).
  3. 올린 뒤 1~3분 기다렸다가, 인터넷이 연결된 상태에서 각 기기에서 앱을 한 번 새로고침(폰은 앱을 완전히 닫았다 다시 열기).
     헤더 배지가 v2.5.0 인지 확인하세요. (이번 v2.4.15 → v2.5.0 에는 예전 화면에 "🔄 새 버전" 안내가 없습니다 — 다음 업데이트부터 뜹니다.)
  4. ★ 모든 기기(PC·폰·팀원)를 v2.5.0 으로 올린 뒤에 쓰세요. 특히 ★ 모든 기기를 올리기 전에는 거래처명·품명 바꾸기와 [사용 중지]를 하지
     마세요 — 예전 판 기기에서 그 거래처를 [수정] 저장하면 "예전 이름" 연결이 지워져 수금·재고가 옛 이름으로 갈립니다(그때는 🩺 데이터 검진의
     [예전 이름으로 잇기]로 되살림). 반품 금액 반영·잔량 마감·은행 수금은 예전 기기에서 표시가 다를 수 있고, 수주 창의 "단가(이번 수주)"는 예전 기기의 출고 창에
     들어가지 않습니다(자료가 깨지지는 않음).
  5. 업데이트 뒤 처음 열 때 자동으로 한 번 정리합니다: 지난 출고·입고(마감한 달과 이번 달 모두)에 그때 단가를 기록(금액은 그대로) · 마감한 달 출고의
     원가 고정 · 청구 개발비의 매출 달 보호 ·
     예전에 한 기기에만 붙여 둔 인쇄사양서를 클라우드로. 바꾸기 전에 📂 백업·복원에 "v2.5.0 … 이행 전 자동보관" 스냅샷을 먼저 남깁니다.
     인쇄사양서를 붙였던 PC 를 한 번 켜 주세요(그 기기에서 올라갑니다).
  6. 팀원은 v2.5.0 을 처음 열 때 기기마다 한 번 "팀 자료로 열까요?"를 확인합니다. 초대받은 적이 없는데 뜨면 [아니오 (이번엔 내 자료로)]를 누르고
     대표에게 확인하세요. [팀에서 나가기…]는 한 번 더 묻고, 나가면 대표가 다시 초대해야 들어올 수 있습니다.
  7. 🩺 데이터 검진을 한 번 돌려 보세요. 예전 판에서 생긴 어긋남(수주 연결이 끊긴 발주 줄 · 없는 출고에 연동된 개발비 · 이름 앞뒤 빈칸 ·
     단가를 찾지 못한 출고 등)이 나오면 그 줄의 [고치기] 버튼으로 정리할 수 있습니다.
  8. 비밀키: 백업 파일·자동 스냅샷에 API 키 등이 더 이상 들어가지 않습니다. 팀원(특히 보기 전용)과 함께 쓰던 중이었다면 예전 스냅샷에
     키가 남아 있을 수 있으니 Claude API 키·카카오 시크릿을 새로 발급받아 바꾸는 것을 권장합니다.
  9. 업데이트 뒤 PC 에서 처음 열 때 백업 파일(박스ERP_백업_날짜.json)이 한 번 자동으로 내려받아집니다 — "주 1회 백업 파일 자동 다운로드"가
     이번부터 기본으로 켜져서입니다(📂 → ⚙️ 자동 백업 설정에서 끌 수 있음). 그리고 👥 팀 창의 "로그인 유지 기한"이 기본 30일이라, 모든 기기가
     이 판을 처음 연 날부터 30일 뒤에 한 번 다시 로그인하게 됩니다(자료 그대로). 번거로우면 팀 창에서 "없음"으로 바꾸세요.

① 파일 설명 (압축을 풀면 나오는 것)
──────────────────────────────────────────────
  upload_to_github/             ← 이 폴더 안의 6개 파일을 GitHub 저장소(drbox-erp) 맨 위(루트)에 올립니다 (폴더째 말고 파일들만)
    index.html                  앱 본체 (= BoxERP_app_same_as_index.html 과 같은 파일, 이름만 index.html). 약 2MB
    manifest.json               앱 이름·아이콘·시작 화면 정보 (홈 화면 설치용)
    sw.js                       오프라인 캐시(서비스워커). 이번 버전은 'box-erp-v25'
    icon-192.png / icon-512.png / icon-512-maskable.png   홈 화면 아이콘
  firebase_rules.json           ← GitHub가 아니라 Firebase 콘솔 "규칙" 탭에 붙여넣는 보안 규칙 (③ 참고). ★ v2.5.0 에서 바뀜 — 다시 붙여 넣기
  BoxERP_app_same_as_index.html ← index.html 과 내용이 같습니다. PC에서 더블클릭해 로컬로만 써보거나, 앱 파일 자체를 보관해 둘 때
  README.txt                    이 문서
  ※ 폴더·파일 이름을 영문으로 한 이유: 압축 파일 안의 한글 이름은 윈도우 기본 압축 해제 시 깨지거나 빠질 수 있어서입니다.

  ※ 앱은 파일 하나(index.html)에 전부 들어 있습니다. 서버 설치나 별도 프로그램은 필요 없습니다.
  ※ 데이터는 index.html 안에 들어 있지 않습니다. 각 기기(IndexedDB)와 Firebase 클라우드에 저장되므로
     index.html 을 새 버전으로 바꿔 올려도 데이터는 그대로입니다.

② GitHub에 올리기 (GitHub Pages)
──────────────────────────────────────────────
[처음 올리는 경우]
  1. https://github.com 로그인 (계정: mechanic1989) → 오른쪽 위 "+" → "New repository"
     · Repository name: drbox-erp   · Public 선택   · "Add a README file" 체크   → Create repository

     · Source: "Deploy from a branch"   · Branch: main  /  (root)  → Save

  2. 올린 뒤 1~3분 기다렸다가, 인터넷이 연결된 상태에서 각 기기에서 앱을 한 번 새로고침(폰은 앱을 완전히 닫았다 다시 열기)하면 새 버전이 열립니다.
     이미 열어 둔 화면에는 "🔄 새 버전이 올라왔습니다 [새로고침]" 안내가 뜹니다.
     · PC 크롬: F5  · 폰: 화면 당겨서 새로고침, 또는 앱을 완전히 닫았다 다시 열기
  3. 헤더의 빨간 배지가 v2.5.0 으로 바뀌었는지 확인. 안 바뀌면 한 번 더 새로고침하거나 브라우저를 완전히 종료 후 재실행.
  4. 이제부터는 저장 뒤 3분 안에 자동으로 백업이 됩니다 (⑥). 헤더의 "☁️ 백업됨 · n분 전" 표시로 확인하세요.

  ※ 앞으로 앱을 수정해 다시 올릴 때는 sw.js 의 VERSION 을 'box-erp-v25', 'v26' … 로 한 칸 올려서 함께 올리면
     모든 기기가 새 버전을 확실히 받고, 오프라인에서도 새 화면이 열리며 "새 버전" 안내가 뜹니다. (이번 v2.5.0 은 v24 로 되어 있으므로 그대로 올리면 됩니다)

③ Firebase 콘솔 설정 (처음 1회 · 이미 했다면 "규칙"만 확인)
──────────────────────────────────────────────
  https://console.firebase.google.com → 프로젝트 drbox-a1fe7
  A. Google 로그인 허용
     · 왼쪽 "빌드" → "Authentication" → "Sign-in method" 탭 → Google 이 "사용 설정됨" 인지 확인 (아니면 켜고 저장)
     · "Settings" 탭 → "승인된 도메인(Authorized domains)" 에 mechanic1989.github.io 가 있어야 합니다. 없으면 "도메인 추가".
       → 이것이 빠지면 로그인 창이 떴다가 "auth/unauthorized-domain" 오류로 닫힙니다.
  B. 데이터베이스 규칙 (팀 공유·자동 백업 저장에 필요) — ★ v2.5.0 에서 바뀌었으므로 업데이트 때 1회 다시 붙여 넣기
     1) 크롬에서 Firebase 콘솔(console.firebase.google.com)에 들어가 박스 ERP 프로젝트(drbox-a1fe7)를 엽니다.
     2) 왼쪽 메뉴 "빌드" → "Realtime Database" → 위쪽 "규칙" 탭.
     3) 규칙 칸의 내용을 모두 지웁니다 (Ctrl+A → Delete).
     4) 새 firebase_rules.json 파일의 내용을 전부 복사해 붙여 넣습니다. (앱에서도 복사 가능: 헤더 👥(팀) → "⚙️ Firebase 보안 규칙" 펼치기 → "📋 규칙 복사")
     5) 오른쪽 위 "게시"를 누릅니다 (빨간 오류 표시가 없어야 함).
     6) 앱을 한 번 새로고침해 평소처럼 저장·동기화되는지 확인합니다. "⚠️ 동기화 실패"가 뜨면 3)~5)를 다시 하세요.
     · 규칙 요약: 본인 데이터는 본인만, 팀원은 초대받은 워크스페이스만 읽고(뷰어) / 쓰기(편집자·관리자). 백업(backups2)도 같은 규칙.
       v2.5.0: 보낸 사람을 속인 초대·남의 워크스페이스 이름 초대·팀원이 스스로 권한 올리기·내보낸 사람의 재참여·팀원이 소유자의 참여 기록을
       바꾸는 것을 막고, 인쇄사양서 한 장 크기를 확인합니다. 혼자 쓸 때도 그대로 동작합니다.
  C. 확인
     · 앱 주소에서 Google 로그인 → 헤더에 이름이 뜨고, 잠시 뒤 "☁️ 백업됨" 이 보이면 정상.
     · "⚠️ 동기화 실패" 또는 "⚠️ 클라우드 백업 실패" 가 뜨면 B의 규칙이 게시되지 않은 것입니다.

④ 첫 실행 · 데이터 이전
──────────────────────────────────────────────
  · Google 로그인 → 이전 버전 데이터가 있으면 새 구조(레코드 단위)로 자동 이전됩니다. 몇 초~수십 초 걸릴 수 있고
    이전 중에는 헤더에 "동기화 준비 중…" 이 표시됩니다. 원래 데이터는 클라우드에 그대로 남습니다.
  · v2.3 이후 기기 저장소는 IndexedDB 입니다. 예전 localStorage 데이터는 첫 실행 때 자동으로 옮깁니다 (5MB 제한 해제).
  · 모든 기기를 v2.5.0 으로 올린 뒤 사용하세요 (⓪-4). 구버전(v2.1 이하)이 남아 있으면 그 기기의 변경이 새 구조에 반영되지 않습니다.
  · 웹 주소(https://mechanic1989.github.io/drbox-erp/)에서는 Google 로그인만 사용합니다. "로컬 모드" 버튼은 HTML 파일을
    더블클릭해 직접 열었을 때만 나타나며, 로컬 모드 데이터는 그 브라우저에만 저장되고 클라우드와 공유되지 않습니다.
    (로컬 모드로 만든 데이터를 계정으로 옮기려면: 로컬 모드 화면에서 💾 백업 → 로그인 화면에서 📂 복원 → 백업 파일에서 복원)
  · 한 번 로그인해 두면 인터넷이 잠시 끊겨도 앱이 열리고 저장되며, 연결되면 클라우드에 반영·백업됩니다.

  · 설치된 앱은 sw.js 덕분에 인터넷이 잠깐 끊겨도 열립니다. (데이터 저장은 되고, 연결되면 클라우드에 반영·백업)
  · 현품표 인쇄 시 우하단 QR(수주번호) → 폰 카메라로 찍으면 해당 수주의 출고 화면이 열립니다.
    앱 안에서는 납기관리 → "📷 QR 출고" (카메라는 https 주소에서만 동작).

⑥ 자동 백업 — 어떻게 동작하나 (v2.4 핵심)
──────────────────────────────────────────────
  [언제]
    · 무엇이든 저장하면 "변경됨" 상태가 되고, 입력이 멈춘 뒤 3분 지나면 스냅샷을 만듭니다.
    · 계속 입력 중이어도 최대 15분마다 한 번은 만듭니다.
    · 앱을 벗어나면(탭 숨김·다른 앱으로 전환·창 최소화) 기다리지 않고 즉시 만듭니다.
    · 앱을 켤 때와 1시간마다 "빠진 변경이 있는지" 점검합니다. 내용이 같으면(해시 비교) 저장하지 않습니다.
    · 다른 기기·팀원이 바꾼 내용도 켜져 있는 기기가 백업합니다. 여러 기기가 켜져 있어도 같은 내용은 한 번만 올라갑니다.
  [어디에]
    · 이 기기: 브라우저 IndexedDB (📂 "이 기기의 스냅샷")  — 최근 10개 + 하루 1개×7일
    · 클라우드: Firebase users/(계정)/backups2  (📂 "클라우드 스냅샷") — 최근 24개 + 하루 1개×30일 + 한 달 1개×12개월
    · gzip 압축으로 저장합니다 (수주 4,000건 기준 5.2MB → 1.0MB). 1회 백업에 화면이 멈추는 시간은 약 0.05초.
  [긴급 보관 (📌)]
    · 엑셀 교체 등으로 200건 넘게 한 번에 삭제되기 직전, 그리고 복원 직전 상태는 별도로 7일간 보관합니다.
  [상태 표시]  헤더(PC) 또는 ☰ 메뉴 맨 위(폰)
    · ☁️ 백업됨 · 3분 전     정상 (로컬 모드는 💾)
    · ⏳ 변경됨 · 2분 후 백업  저장한 내용이 있고 곧 백업 예정
    · ⏫ 백업 중…            저장 중
    · 📴 오프라인             인터넷 끊김. 연결되면 자동으로 백업
    · ⚠️ 클라우드 백업 실패   2분→4분→…최대 30분 간격으로 자동 재시도. 계속되면 ③-B 규칙 확인
    · 클릭하면 📂 백업·복원 창이 열립니다.
  [설정]  📂 백업·복원 → "⚙️ 자동 백업 설정"
    · 유휴 대기(1~10분) · 최대 간격(5~60분) · 클라우드 백업 켜기/끄기 · 이 기기 스냅샷 켜기/끄기

      박스ERP_백업_날짜.json 을 다운로드 폴더에 자동 저장합니다. → 이 파일을 USB나 구글드라이브에 옮겨 두면 완전한 3중 백업.
      (끄려면 체크를 풀면 됩니다. 폰에서는 자동 다운로드를 하지 않고 홈에 "마지막 파일 백업 n일 전"만 보입니다.)
  [파일 백업]  헤더 💾 백업 (또는 📂 → "파일로 내려받기")
    · 인쇄사양서 이미지까지 포함한 전체 백업 파일(.json). 자동 스냅샷은 용량 때문에 이미지를 뺍니다.
    · 홈 화면에 "💾 마지막 파일 백업 n일 전 · [지금 받기]"가 늘 보입니다(14일 넘으면 주황). 월 1회 이상 권장.
  [복원 미리보기 · 백업 파일 검사]  📂 백업·복원
    · [복원]을 누르면 바로 바꾸지 않고 "지금 자료와 무엇이 달라지는지"(자료 종류마다 +생김 / −없어짐 / ~바뀜 건수, 백업 시각·버전·만든 기기)를
      먼저 보여 주고 [이대로 복원]을 눌러야 바뀝니다. 그래도 "복원 전 자동보관"은 남습니다.
    · [🔍 백업 파일 검사]: 백업 파일을 복원하지 않고 시각·버전·자료 종류별 건수·손상 여부만 확인합니다(지금 자료와 비교 포함).

⑦ 문제가 생겼을 때 — 복구 방법
──────────────────────────────────────────────
  ※ 앱 안 [❓ 도움말] → 🧰 문제 해결에도 같은 안내가 증상별로 있고(바로가기 버튼 포함), 해결이 안 되면 🩺 진단 보고서를 [📋 복사]해
     도우미(또는 AI)에게 붙여 넣어 보내 주세요(거래처명·금액은 들어가지 않음).
  ※ 로그인 화면에 "로그인 유지 기한이 지나…" 또는 "소유자(관리자)가 이 기기의 접속을 끊었습니다"가 뜨면 그냥 다시 로그인하면 됩니다
     (자료 그대로 · 올라가지 않았던 변경도 이어서 올라감). ⑨ 참고.
  A. 레코드 하나를 잘못 고쳤다 / 잘못 지웠다 / 잘못 추가했다
     → 헤더 🕘 이력 → 해당 줄의 "↩ 이전 상태로" / "↩ 복원" / "↩ 추가 취소" 클릭. 그 한 건만 되돌아갑니다.
     → 삭제 직후라면 화면 우하단 토스트의 "↩ 되돌리기", 또는 🕘 이력 → 🗑 휴지통에서도 복원됩니다.
  B. 엑셀을 잘못 올려서 목록 전체가 바뀌었다 / 여러 건이 한꺼번에 잘못됐다
     → 📂 백업·복원 → "이 기기의 스냅샷" 맨 위의 📌 "일괄삭제 전 자동보관" 또는 그 직전 시각의 스냅샷 → 복원
     → 복원은 모든 데이터를 그 시점으로 되돌립니다. 복원 직전 상태도 "복원 전 자동보관" 으로 남으니 다시 되돌릴 수 있습니다.
     → 확인 창 → "복원 완료" → 자동 새로고침. 로그인 상태면 클라우드도 함께 그 시점으로 바뀝니다 (팀원 화면도 동일).
  C. 기기를 잃어버렸다 / 브라우저 데이터를 지웠다 / 새 PC
     → 새 기기에서 주소 열고 같은 Google 계정으로 로그인 → 클라우드 데이터가 그대로 내려옵니다.
     → 클라우드까지 잘못됐다면 📂 → "클라우드 스냅샷" 에서 시각을 골라 복원.
  D. 인터넷이 끊긴 채로 입력하다가 앱을 닫았다
     → 그 기기에서 다시 열면 "지난번 저장되지 않았던 변경 n건을 클라우드와 병합했습니다" 안내가 뜨고 자동으로 합쳐집니다
       (같은 레코드를 양쪽에서 고쳤으면 나중에 고친 쪽이 남습니다 — ⑨ 참고). 🕘 이력에 "병합" 으로 기록됩니다.
     → 아직 클라우드에 안 올라간 변경이 있는 상태에서 창을 닫으려 하면 브라우저가 경고합니다. 잠시 후 다시 시도하세요.
  E. "데이터가 손상되어 읽을 수 없습니다" 경고가 떴다
     → 매우 드문 경우입니다(기기 저장소 파손). 원문은 "손상 데이터 원문 보관" 스냅샷으로 남고, 📂 에서 직전 스냅샷을 복원하면 됩니다.
  F. 백업 파일(.json)로 복원
     → 📂 → "백업 파일(.json)에서 복원" → 파일 선택 → "지금 자료와 무엇이 달라지는지" 표(종류마다 +생김 / −없어짐 / ~바뀜 건수와
       백업 시각·버전·만든 기기)를 확인 → [↩ 이대로 복원]. v2.1 이후 어떤 버전의 백업 파일도 복원됩니다. 복원 직전 상태는 "복원 전 자동보관"으로
       남으니 잘못 복원했으면 📂 에서 그 스냅샷을 다시 복원하면 됩니다. 복원하지 않고 파일만 확인하려면 [🔍 백업 파일 검사].
  G. 로그인이 안 된다
     → ③-A 승인된 도메인 확인 / 팝업 차단 해제.
     → 폰 브라우저(삼성 인터넷 등)에서 로그인을 눌러도 다시 로그인 화면으로 돌아오면: 브라우저 추적 방지 때문에 로그인 결과를
       못 받는 경우입니다. v2.4.2 부터는 팝업 방식으로 로그인하므로 해결되며, 그래도 안 되면 크롬 브라우저로 열거나
       삼성 인터넷 설정 → 개인정보 보호 → "스마트 추적 방지" 를 끄고 시도하세요. 카카오톡 안에서 열면 정상 동작합니다.
  H. 새 버전이 안 보인다
     → 인터넷이 연결된 상태에서 새로고침(폰은 앱 완전히 닫고 다시 열기). 그래도 안 되면 브라우저 완전 종료 후 재실행,
       PWA 는 삭제 후 다시 설치 (데이터는 계정에 있으므로 안전).
  J. 업데이트 뒤 숫자가 달라 보인다
     → 의도된 변화인 경우가 많습니다: 부가세가 모든 화면에 붙어 "계산서 발행 업체" 체크가 없던 거래처의 미수금이 늘어 보일 수 있고(거래명세표와
       같은 금액), 수금관리가 거래처 잔액 기준이 되어 초과 입금이 있던 거래처의 미수금은 줄어 보이며, 재고시트의 '입고 예정'은 발주한 수량만
       세고 재고금액은 매입가 기준입니다. 자세한 것은 ⑩ v2.5.0 항목. 그래도 이상하면 🩺 데이터 검진 → 그 줄의 설명을 보세요.
  I. "⚠️ 기기 저장 실패" 가 뜬다
     → 저장공간이 꽉 찼거나 사생활 보호 모드입니다. 일반 창에서 열고, 📂 창 상단의 저장소 용량을 확인하세요.

⑧ 안정 운영 수칙 (꼭 지켜주세요)

  1. 소유자 계정은 하나로. 팀원은 👥 팀 에서 초대해 같은 데이터를 씁니다. (각자 로그인해서 따로 쓰면 데이터가 갈라집니다)

  4. 엑셀로 대량 교체하기 전에는 📂 → "🕒 지금 백업" 을 한 번 눌러 두면 더 안전합니다 (안 눌러도 긴급 보관은 자동으로 됩니다).

     📂 백업·복원 창에서 "🔑 비밀키도 파일에 넣기"를 고르세요 (키가 든 파일은 다른 사람에게 보내지 말 것).
     세금계산서 연동 비밀키는 그 기기에만 저장됩니다 (다른 기기에서 쓰려면 그 기기에서 다시 입력).
  7. Firebase 무료(Spark) 용량: 저장 1GB · 다운로드 10GB/월. 클라우드 스냅샷은 최대 300MB 까지만 보관(넘으면 오래된 것부터 정리).
     앱을 열 때 받는 자료 크기는 📂 백업·복원 창의 "앱을 열 때 받는 자료"에 나옵니다. 수주가 수천 건을 넘으면 앱을 자주 껐다 켜기보다
     켜 둔 채 쓰는 것이 다운로드를 줄입니다. 콘솔 → Realtime Database → "사용량" 에서 가끔 확인.

⑨ 팀 공유 사용법
──────────────────────────────────────────────
  소유자 계정으로 로그인 → 헤더 👥 → 이메일·역할 입력 → 초대.
  초대받은 사람이 같은 주소에서 자기 Google 계정으로 로그인하면 "팀 초대가 와 있습니다(보낸 사람·역할)" 창이 뜨고 [참여하기]를 눌러야
  들어옵니다 (v2.5.0 — 예전에는 묻지 않고 자동 참여). 모르는 사람이 보낸 초대는 [거절]. 팀원은 v2.5.0 을 처음 열 때 기기마다 한 번
  "팀 자료로 열까요?"를 확인합니다.
  역할: 관리자(모든 일 + 멤버 관리) / 편집자(입력·수정·삭제 — 복원·마감/마감 취소·여러 건 한꺼번에 삭제·엑셀 올리기는 소유자·관리자만) /
  뷰어(보기만 — 입력·수정 버튼과 선택 체크칸이 숨겨짐). 역할을 바꾸면 그 사람의 열린 화면에도 바로 반영됩니다.
  소유자·관리자는 👥 팀 창에서 직원(편집자·뷰어)에게 매입단가·원가·손익을 가릴 수 있고(화면에서만 — 아래), 로그인 유지 기한과
  기기 [접속 끊기]로 분실·공용 기기에 대비할 수 있습니다.
  저장은 기록(수주 한 건·거래처 한 곳 등) 단위로 반영됩니다. 여러 사람이 동시에 입력해도 서로 다른 기록은 덮어쓰지 않습니다.
  같은 기록을 두 사람이 고칠 때: 수주·발주 줄·제품·거래처·개발비 수정 창과 [📅 납기·납품처] 창은 저장하면 그 창에서 바꾼 칸만 저장되고,
  창을 연 사이 다른 사람이 바꾼 칸은 그대로 남습니다. 같은 칸을 둘 다 바꿨으면 두 값을 보여 주고 어느 쪽으로 할지 묻습니다.
  다만 두 기기가 거의 같은 순간(1초 안팎) 같은 기록을 저장하거나, 인터넷이 끊긴 기기에서 고친 것이 나중에 연결되면 그 기록은 나중에
  도착한 저장으로 바뀝니다. 같은 건은 한 사람이 고치는 것이 안전합니다. (반품·견적·목형·입고/출고 수량·수금 수정은 같은 기록을 동시에
  고치면 나중 저장이 이깁니다.) 인터넷이 끊긴 기기에서 고친 기록과 다른 기기에서 고친 같은 기록은, 다시 연결될 때 나중에 저장된 쪽으로
  기록 전체가 남습니다(예: 끊긴 폰에서 수주 비고, PC 에서 같은 수주의 납기를 고쳤다면 폰이 나중이면 납기가 예전 값). 앱을 막 열어
  "동기화 준비 중…"일 때 넣은 것은 사라지지 않고 합쳐집니다.
  🕘 이력에서 누가·언제·무엇을 바꿨는지, 휴지통에서 삭제 항목 복원. 백업은 팀 데이터 전체가 대상입니다.

  [공용 PC · 폰 분실 대비]
  · 앱 잠금: 👥 팀 창(폰은 ☰ 메뉴)의 [🔒 앱 잠금] — PIN 4~6자리와 "쉬면 잠금" 시간을 정합니다. 잠긴 화면에서는 금액이 보이지 않고,
    PIN 을 잊으면 로그아웃 → Google 로 다시 로그인하면 풀립니다(자료는 계정에 있어 안전).
  · 공용 PC 에서는 [로그아웃] 창의 "이 기기에 남은 자료·스냅샷 지우기"를 고르세요. 다른 계정이 같은 기기로 로그인해도 앞 계정의
    자료·스냅샷은 보이지 않고, 아직 올라가지 않은 변경은 따로 보관했다가 원래 계정으로 다시 로그인하면 올라갑니다.
  · 로그인 유지 기한: 👥 팀 창 → "⏱ 로그인 유지 기한"(7일 / 30일(기본) / 90일 / 없음). 기기마다 마지막 로그인부터 이 기간이 지나면 앱을 열 때
    자동으로 로그아웃되고 "다시 로그인해 주세요"가 나옵니다(자료 그대로 · 올라가지 않은 변경은 먼저 올림). 팀의 모든 기기에 적용됩니다.
  · 기기 [접속 끊기]: 👥 팀 창의 멤버 줄 아래에 그 사람이 로그인한 기기(종류·앱 버전·마지막 접속 — 이름·자료는 기록하지 않음)가 나옵니다.
    폰을 잃어버렸거나 공용 PC 에 로그인한 채 두었으면 [접속 끊기] → 그 기기는 바로 로그아웃됩니다(다시 로그인하면 다시 쓸 수 있으니
    완전히 막으려면 [제거] 또는 역할을 뷰어로). 소유자 자신의 기기도 끊을 수 있습니다(지금 쓰는 기기는 "(이 기기)").

  [직원 화면에서 매입단가·원가·손익 가리기]
  · 👥 팀 창 → "🙈 직원 화면에서 가릴 것"에서 편집자·뷰어를 체크하면, 그 역할의 모든 기기에서 💹 손익분석·📋 매입원장 탭, 홈의 손익 현황·
    목표·월별 차트·거래처별 손익·이번달 발주액, 재고시트의 매입단가·재고금액, 제품·수주·발주·입고 창의 매입단가 칸, 발주서의 단가·금액,
    개발비 매입금액, 변경이력의 매입단가 값, 엑셀 다운로드의 매입 열이 가려집니다. 세금계산서 준비·매출원장·수금·거래명세표는 그대로.
  · ★ 화면에서만 가립니다(자료는 그 기기에 있음) — 백업 파일에는 모든 자료가 들어가므로, 자료 자체를 직원에게 주지 않으려면 뷰어 역할·[제거]를
    함께 쓰세요. 소유자·관리자 화면은 가려지지 않습니다.

⑩ 버전별 변경 요약
──────────────────────────────────────────────
  v2.5.1 (이번) — 쓰면서 나온 요청 세 가지
   · 📐 재고 조정(재고시트 줄의 [📐 조정]): 창고에서 세어 본 수량을 넣으면 앱 재고와의 차이만큼 조정 기록이 생깁니다(사유: 실사 차이·파손·폐기·분실·
     입고 누락·출고 누락·기타 + 메모). 재고 수량만 맞추고 매입원장·손익·미수금은 바뀌지 않습니다. 늘리는 조정은 그 날짜의 로트로(재고금액은 적은
     매입단가로), 줄이는 조정은 오래된 로트부터 빠집니다. 같은 창에서 조정 기록을 지울 수 있고(휴지통 보관) 변경이력·동기화·백업에 들어갑니다.
     실제로 들어온 물건이 빠진 거면 조정 대신 입고관리에서 [입고처리]하세요(매입이 잡혀야 하므로).
   · 입고일 변경: 입고관리 [수량 수정] 창에 입고일 칸이 생겼습니다. 바꾸면 매입원장·재고 로트의 날짜가 함께 바뀌고 입고번호는 그대로입니다.
     마감한 달로는 옮길 수 없고, 그 수주의 출고보다 뒤 날짜로 옮기면 한 번 확인합니다.
   · 수주관리 상태 필터에 "🚚 미완료(출고 전·부분출고)"와 "✅ 완료(출고완료·잔량 마감)"가 생겼고, 고른 상태를 이 기기에 기억합니다 — 납기일을
     바꾸거나 검색할 때 끝난 수주가 섞이지 않게 "미완료"로 두고 쓰면 됩니다.
   · 매입단가 소급: 제품마스터에서 매입단가를 바꾸면 "적용 시작일"을 묻고, 그 날짜 이후 이미 입고한 건(열린 달)의 매입단가도 바꿀지 묻습니다.
     [확인]하면 매입원장·부가세 자료와 그 수주로 나간 출고의 원가(손익)가 함께 바뀌고, [취소]하면 지난 입고는 그대로(새로 입고하는 것부터 새 단가).
     마감한 달의 입고는 그대로입니다(필요하면 마감취소 뒤). 한 건만 고칠 땐 입고관리 [수량 수정]의 매입단가 칸. 판매단가는 전처럼 단가 변경 때
     "이미 출고한 건도 바꿀까요?"로 소급하고, 출고 한 건의 단가는 납기관리 ✏️ 수정에서 고칩니다.
   · 입고 [선택취소] 안내: 미입고 줄을 체크했거나 이미 출고된 수주의 입고를 취소하려 할 때 어느 줄을 체크해야 하는지·먼저 무엇을 해야 하는지 알려 줍니다.

  v2.5.0 — 정밀 검토(8개 구역·202건 발견, 겹침 제외 약 150건)에서 나온 문제·보완점·취약점을 한 번에 고치고, 고친 판을 독립 검토자 3명이
           다시 깨뜨려 찾은 53건과 채점자가 뽑은 보강 항목(도움말·폰·보안·기능)까지 더해 넣고, 그 판을 한 번 더 검토(R4 11건)·채점한 뒤
           남은 보강 항목(목록 정렬·복원 미리보기·수주 단가·홈택스 매출 대조·원가 가리기·기기 끊기 등)까지 넣음(6단계).
           아래는 사용자에게 보이는 변화만 간추린 것. ★ 는 숫자·동작이 달라져 보일 수 있는 것.

  [금액 · 부가세 · 단가]
   · ★ 부가세가 모든 화면에서 같아졌습니다 — 거래명세표·매출원장·수금관리·미수금·세금계산서 준비·홈·여신 모두 공급가의 10%.
     예전에 "계산서 발행 업체" 체크가 없던 거래처는 수금관리·미수금에 부가세가 새로 붙어 미수금이 늘어 보일 수 있습니다(거래명세표와
     같은 금액이 된 것). 실제로 부가세를 받지 않는 거래처라면 받은 금액대로 수금을 넣으면 됩니다.
   · "계산서 발행 업체" 체크는 "세금계산서 발행 대상"으로 이름이 바뀌었습니다 — 세금계산서 준비 화면의 발행 목록에 넣을지만 정합니다. 새 거래처는 켜진 채로 시작.
   · 단가 고정: 출고할 때의 판매단가와 입고할 때의 매입단가가 그 기록에 남습니다. 제품마스터의 단가를 바꿔도 이미 출고·입고한 금액은 바뀌지 않습니다.
     출고 창·✏️ 출고 수정에 줄마다 단가 칸이 생겨 특가·샘플(0원)을 넣을 수 있습니다.
   · 단가를 지난 날짜부터로 바꾸면 그 날짜 이후가 모두 새 단가가 되고(마감한 달은 그대로), 열린 달에 이미 출고한 건이 있으면
     "이 날짜 이후 이미 출고한 n건도 새 단가로 바꿀까요?"를 묻습니다. 단가 예약은 적용일이 지나면 제품마스터에도 보이고, [수정]으로 단가를
     고쳐도 예약이 남으며, 단가 예약 창의 [🗑 예약 취소]로 뺄 수 있습니다.
   · 제품마스터의 "발주단가 (원/㎡)"는 "매입단가 (원/매)"로 이름만 바뀌었습니다(계산은 원래부터 1매당).
   · 1원 차이(홈 총 미수금 ↔ 수금관리, 명세서 줄 세액 합 ↔ 합계 세액, 손익 운반비 합)가 없어졌습니다.

  [이름 바꾸기 · 삭제]
   · 거래처명·발주처명·품명을 바꾸면 저장 전에 무엇이 바뀌고 무엇이 옛 이름으로 남는지 보여 줍니다. 지난 거래 기록(출고·입고·수금·세금계산서 등)은
     옛 이름 그대로 남고, 금액·미수금·세금계산서·재고는 새 이름과 이어서 계산됩니다. 옛 이름은 "예전 이름"으로 기억되어 같은 이름으로
     다른 거래처를 새로 등록할 수 없습니다. ★ 모든 기기를 v2.5.0 으로 올린 뒤에 이름을 바꾸세요.
   · 품명이 같은 다른 거래처의 단가를 가져다 쓰지 않습니다(품명만으로 찾는 것은 그 품명의 제품이 하나뿐일 때만).
   · 제품·거래처 [삭제]는 쓰이는 건수(수주 n건·출고 n건…)를 보여 주고 확인받습니다. 지우지 않고 숨기려면 [사용 중지]. 견적·반품·자산 삭제도 확인창이 뜹니다.
   · 수주관리 [↩ 선택 취소] 버튼 이름이 [🗑 선택 삭제]로 바뀌었습니다(하는 일은 같음, 바로 [↩ 되돌리기] 가능).

  [수주 · 발주 · 입고]
   · 제품을 [수정]으로 열어 단가만 고쳐 저장해도 적재방수·1파렛트 수량이 바로 전에 연 제품 값으로 바뀌던 문제를 고쳤습니다.
   · 수주 저장 때 수량(1 이상 정수)·수주일자·납기일(수주일보다 앞이면 안내)을 검사합니다. 거래처·품명·수량을 바꿔 저장할 때도 여신 한도를 확인합니다.
   · 발주서를 낸 수주는 수주관리에서 잠깁니다. 수량·품명을 바꾸려면 발주관리에서 [발주취소] 뒤 [수정]. 납기일·납품처는 [📅 납기·납품처]로 언제든.
     수주 [수정] 저장이 이미 입고완료된 줄의 수량까지 덮어쓰던 문제를 고쳤습니다.
   · 수주 창: 거래처의 등록 납품처가 목록으로 나오고, 고른 납품처의 주소·연락처가 발주서(비고란)와 거래명세표에 찍힙니다.
     품명을 치수·원지가 비어 있는 제품으로 바꿀 때 앞 제품의 치수·원지가 남던 것, 창을 열어 둔 채 날짜가 바뀌면 어제 날짜·번호로 저장되던 것을 고쳤습니다.
   · ★ 수주 창의 "📦 재고에서 출고(발주 안 함)": 창고 재고로 바로 납품하는 수주 — 발주·입고 줄을 만들지 않고 그 품목의 남는 재고에서 출고합니다.
   · ★ 발주관리 [＋ 재고용 발주]: 수주 없이 재고를 채우는 발주(안전재고 보충). 재고시트의 "🚨 발주 필요" 줄에서도 [📦 발주]로 바로 엽니다.
   · 발주 [수정] 창에서 발주처·수량·납기일 외에 매입단가·비고도 고칠 수 있습니다(발주처만 바꾸고 단가가 그대로면 한 번 확인). 발주 수량을 바꾸면 입고 대기 줄도 따라옵니다.
     제품마스터의 발주처·매입단가·원지를 고치면 그 품목의 미발주 수주에 반영할지 묻습니다. 발주서는 발주한 때의 내용(치수·원지·적재)으로 재출력됩니다.
   · 발주일은 화면·첫 발주서·재출력 모두 실제 발주한 날입니다. 분할 발주 번호(-1, -2…)가 다른 발주와 겹치거나, 취소한 발주번호가 같은 날 다른 수주에
     다시 쓰이던 것, 두 발주처로 나눈 분할 발주의 입고 줄이 어긋나던 것을 고쳤습니다. 발주서는 첫 출력과 재출력의 줄 순서가 같고(수주번호 → 품명),
     납기요청일은 줄마다 그 줄의 납기, 원지구성이 길어도 겹치지 않습니다. 발주서에 단가·금액·우리 회사 연락처를 넣을 수 있습니다(선택).
   · 이미 발주완료인 줄을 체크하고 [발주]를 눌러도 다시 발주되지 않습니다. 발주관리 [🗑 선택 삭제]는 "삭제불가" 줄을 지우지 않습니다.
   · 입고관리: 입고일을 고를 수 있고, 입고 수량은 [수량 수정]으로 고칩니다(입고취소 후 다시 입고할 필요 없음). 일괄 입고도 발주 여부를 확인합니다.
     발주처 칸·발주처 검색·"납기 지난 미입고" 표시가 생겼습니다. 부분 입고 뒤 남은 줄의 입고 예정일이 입고한 날로 바뀌지 않습니다.
   · ★ [잔량 마감]: 모자라게 들어오고 끝난 입고 줄(입고관리), 모자라게 나가고 끝난 수주(납기관리 [✂️ 잔량 마감])를 닫습니다 — 미입고·미출고·재고시트·여신에서
     빠지고 기록·매출은 그대로, [잔량 마감 취소]로 되돌릴 수 있습니다.
   · 이미 출고된 수주의 [입고취소]는 막고 안내합니다(출고를 먼저 취소). 입고취소해도 목형·인쇄판 사용횟수가 맞게 계산됩니다(입고 기록에서 계산).
   · 변경이력 되돌리기·휴지통 복원이 발주·입고 줄과 어긋나지 않습니다 — 함께 바뀐 줄까지 되돌리거나, 되돌릴 수 없는 기록은 "ℹ️ 되돌리는 법"을 보여 줍니다.
     발주·입고 줄이 없어진 수주는 데이터 검진 "발주·입고 줄이 없는 수주"에서 다시 만들 수 있습니다.
   · 예전 판에서 발주 [수정]으로 수주 연결이 지워진 발주 줄은 🩺 데이터 검진 → "수주 연결이 끊긴 발주 줄" → [수주에 연결]로 바로잡습니다.
   · 수주번호가 비어 있는 수주(엑셀로 생김)를 삭제해도 다른 수주·발주 줄이 함께 지워지지 않습니다. 지운 수주·거래처·발주 번호는 다시 쓰지 않습니다.
   · 거래처 등록: 저장하지 않은 새 거래처의 납품처가 다음 거래처에 붙던 것, 삭제한 거래처의 납품처가 남던 것을 고쳤습니다. 제품 등록 때 거래처 이름을 검사합니다.

  [출고 · 거래명세표 · 현품표 · 재고]
   · ★ 출고취소가 바뀌었습니다: 납기관리 줄의 ↩ 는 그 줄의 출고 한 번만 취소합니다(예전: 그 수주의 출고 모두). [↩ 선택 취소]도 체크한 줄만.
     취소하면 연동된 개발비는 다시 '미연동'이 되어 다음 출고 때 연동되고(예전에는 없는 출고번호에 연동된 채 남아 손익에서 빠졌음), 운반비는 같은 출고의 남은 품목에 남습니다.
   · 여러 품목을 한 창에서 출고할 때 수량 0 인 품목(입고 부족으로 빠진 품목)의 개발비는 연동되지 않습니다.
   · 출고 창: 같은 품목의 남는 재고(여유분 입고·재고용 발주·반품 복귀)를 꺼내 쓸 수 있고(확인), 입고일보다 이른 출고일이면 안내, 출고 직후 [🖨️ 거래명세표],
     [📷 QR로 품목 더 담기](한 차에 여러 품목을 한 출고번호로).
   · ✏️ 출고 수정은 입고보다 많은 수량·음수·빈칸·먼 날짜를 받지 않습니다. 품목을 빼려면 수량 0.
   · 수주관리 [🖨️명세]: 나눠 나간 수주는 출고번호를 골라 뽑습니다(납기관리 🖨️ 와 같은 문서 — 예전에는 전체 수량 × 마지막 단가로 나왔음).
   · 거래명세표: 여러 쪽이면 마지막 쪽에 총 합계, 긴 품명·상호도 끝까지(13자 넘는 상호가 잘리던 것), 개발비 줄이 수량 합계에 1 더해지던 것, 메모는 출력 창에서 직접,
     납품처가 있으면 To: 줄에, 줄 세액 합 = 합계 세액.
   · 납기관리: 정렬이 동작하고(납기일 ▲ 등), "입고수량" 칸이 그 수주의 입고 합계로 나오며(나눠 입고한 수주가 첫 입고분만 보이던 것), QR 출고 뒤 검색창에
     수주번호가 남지 않고, 수주번호·납품처 검색이 출고 기록 없는 수주에도 됩니다. 출고완료 줄의 납기 칸은 "납기 준수" 또는 "지연 n일".
   · ★ 재고시트: '입고 예정'은 발주한 수량만, 아직 발주 안 한 수주는 '미발주' 칸 — 발주를 잊으면 "🚨 발주 필요"와 홈 카드로 알려 줍니다
     (예전에는 미발주 수량이 '곧 들어올 수량'으로 세어져 경고가 뜨지 않았음). 재고금액은 매입가 기준(판매가 기준은 따로 표시). 안전재고는 곧 나갈 수주분을 뺀 재고로 판단.
     반품에서 "재고로 되돌림"한 수량이 현재고에 더해집니다.
   · 차량 추천: 가장 큰 차에도 다 못 싣는 양이면 그렇게 표시하고, 수량 오타(0 여러 개)에 화면이 멈추지 않습니다.
   · 홈 달력 날짜 창의 상태가 늘 "접수"로 나오던 것 → 미발주·미입고·출고대기·부분출고·재고 출고 등 실제 단계로.
   · 당사정보를 넣지 않았을 때의 확인 창이 문구와 반대로 동작하던 것, 브라우저가 새 창을 막으면 견적서 [인쇄]·[현품표]가 반응 없던 것을 고쳤습니다.
   · 폰 카메라로 QR 을 찍어 앱이 새로 열릴 때 자료 동기화가 끝나기 전에 "찾을 수 없습니다"가 뜨던 것을 고쳤습니다. AI 도우미에 납기일·출고수량·미수금(거래처 잔액 기준)이 바르게 들어갑니다.

  [원장 · 수금 · 세금계산서 · 손익 · 반품 · 홈]
   · ★ 수금관리가 "거래처 잔액" 기준이 되었습니다. 한 달에 청구보다 더 받은 돈은 가장 오래된 미수 달부터 자동으로 채워지고, 다 채우고 남으면 선수금으로
     따로 보입니다. 그래서 예전에 초과 입금이 있던 거래처는 총 미수금이 줄어 보일 수 있습니다(실제 남은 돈). 출고일을 다른 달로 옮겨 청구가 없어진 달의
     수금도 사라지지 않고 "청구 없음·선수금"으로 보입니다. 6개월보다 오래된 미수 달도 내역에 "이전 미수"로 보입니다.
   · 수금 입력: 청구연월 맨 위 "⚡ 오래된 미수 달부터 자동 배분"을 고르면 금액·날짜만 넣어도 오래된 달부터 나눠 넣습니다(미리보기·확인창).
     출고 전에 받은 돈은 "청구 없음 · 선수금" 달을 고르세요. 수금 내역의 [✏️ 수정]에서 청구연월을 바꾸면 그 달로 옮겨집니다(예전처럼 두 번 잡히지 않음).
     지난달 청구분의 수금도 오늘 날짜로 넣을 수 있습니다(잠금은 수금일 기준).
   · 📒 거래처 원장(수금관리 필터 바·연체 현황의 📒): 거래처·기간을 고르면 이월 잔액 → 날짜순 출고·개발비·반품·부가세·수금 → 잔액. 인쇄·엑셀.
   · ★ 반품/불량 화면: 기본은 지금처럼 기록만이고, 등록할 때 "재고 처리 → 재고로 되돌림", "금액 처리 → 매출에서 차감"을 고르면 재고와
     매출·미수금·세금계산서 준비·손익에 반영됩니다. 구분 "± 매출 가감"으로 운반비 청구·단가 조정·에누리처럼 출고가 아닌 매출 증감(+/−)을 넣을 수
     있습니다(매출원장의 [± 매출 가감 입력]). 마감한 달 날짜로는 금액 반영을 넣을 수 없으니 이번 달 날짜로. 목록의 [수정]으로 고칠 수 있고,
     "이번달" 건수가 매월 1일 오전 9시 전에 지난달로 나오던 것을 고쳤습니다.
   · ★ 청구 개발비는 연동한 출고일의 달(거래명세표와 같은 달) 매출입니다 — 매출원장·수금·세금계산서 준비·손익·엑셀 모두 같은 달.
     업데이트 전에 이미 마감했거나 세금계산서를 발행한 달의 개발비는 그 달 그대로 둡니다. 개발비 [수정] 창이 다른 품목이 선택된 채 열리던 것을 고쳤습니다.
   · 손익분석에 개발비(청구 마진·당사 부담)와 반품·매출 가감이 줄로 들어가 매출이 매출원장과 같고, 줄을 더한 값·카드·합계·홈이 같습니다.
     "월별 순이익 추이" 차트의 원가는 표와 같은 기준(그때 매입단가). 목표 달성률은 어디서나 "이번 달 순이익 ÷ 월 목표".
   · 홈: "이번달 발주액"은 발주서를 낸 금액(발주일 기준), "미입고 발주"는 덜 들어온 남은 수량, "납기 임박·지남"에 납기가 지난 미출고도 나오고,
     "전월 대비"는 지난달 같은 날까지와 비교합니다. "매입액(원가)"는 "매출원가 (출고분)"으로 이름만 바뀌었습니다. 홈의 총 미수금 = 수금관리.
   · 엑셀(CSV): 매출원장·매입원장·손익분석 파일이 화면과 같은 줄(개발비·반품 포함, 맨 끝 '구분' 열). 세금계산서 "작성일자 기준"을 '마지막 납품일'로 하면
     발행 데이터 엑셀도 그 날짜. 이름이 - = + @ 로 시작하는 칸은 앞에 ' 가 붙습니다(엑셀이 수식으로 읽지 않게).
   · 앱을 켜 둔 채 달이 바뀌면 원장·손익·수금·세금계산서 준비의 기본 기간이 새 달로 바뀝니다. [이번 달]·[지난달] 버튼. 매입원장이 자료가 많아도 느려지지 않습니다.

  [마감 · 세금계산서 발행완료]
   · ★ 마감의 잠금 기준이 그 거래의 날짜입니다. 지난달을 마감해도 지난달에 받은 수주의 남은 수량은 오늘 날짜로 발주·입고·출고할 수 있고,
     지난달 청구분의 수금도 오늘 날짜로 넣을 수 있습니다. 마감한 달 날짜의 기록은 개발비·되돌리기·휴지통 복원·엑셀·검진 [보정]으로도 바뀌지 않습니다.
   · 마감할 때 그 달 합계를 기록해 두고, 나중에 달라지면 마감관리에 "⚠️ 마감 뒤 달라짐"으로 알려 줍니다. 이번 달을 마감하려 하면 한 번 더 묻습니다.
   · 세금계산서 [발행완료]로 표시한 달의 출고를 고치거나 취소하면 확인창이 뜨고, 금액이 달라지면 세금계산서 준비 화면에 "발행 후 금액 변경"으로 표시됩니다.

  [엑셀 · 데이터 검진 · 검색 · 견적 · 계산기]
   · 엑셀 업로드: 올리면 먼저 '바뀌는 줄 · 그대로 · 새로 추가 · 오류' 확인 창이 뜨고, 오류 줄(날짜·숫자를 읽을 수 없음, 마감된 달, 고칠 수 없는 칸 등)은 반영하지 않고
     이유를 보여 줍니다. '모두 추가 (중복 허용)' 버튼은 없앴습니다(같은 자료가 두 벌 생기던 원인). 잘못 올렸으면 [↩ 이번 업로드 되돌리기](변경이력에서도).
   · 발주·입고·출고 엑셀은 기존 줄의 몇 칸만 고칠 수 있습니다(발주: 수량·납기일·발주처·비고 / 입고: 입고일·수량(미입고) / 출고: 출고일·수량·운임).
     업체명·품명 바꾸기는 엑셀이 아니라 [수정] 창에서.

       그런 줄은 수주의 납품처를 바꿔도 따라가지 않으니 보내기 전에 미리보기에서 확인하고, 다르면 발주 뒤에 발주관리의 [📅 납기·납품처]로 고쳐 재출력
   · (v2.4.15) 발주서 표의 비고 칸을 조금 넓힘 (전장·전폭·장×폭×고 칸의 남는 폭을 가져옴 · 그 밖의 칸은 재출력 발주서 기준 그대로).
     첫 출력과 재출력의 칸 폭이 조금 달랐던 것도 같게 맞춤
   · (v2.4.15) 발주관리에서 미발주 건을 [수정](수량·납기일·발주처)으로 저장하면 수주와의 연결이 지워지던 것 바로잡음.
     연결이 지워진 줄은 — 발주해도 입고관리에 "미발주 (발주 후 처리)"로 남아 입고처리를 할 수 없었고 · 수주관리에서는 발주 전으로 보여 수정·삭제가 됐고 ·
     발주취소 때 같은 품목 다른 수주의 줄과 합쳐졌고 · 분할 발주의 남은 줄은 "-2" 대신 새 번호로 나갔음. 이제 [수정]으로 저장해도 연결이 유지됨.
     ※ 이미 연결이 지워진 줄은 자동으로 되살리지 않음
     ※ 분할 발주의 남은 줄을 [수정]에서 다른 발주처로 바꿔 발주할 때: 먼저 발주한 것이 입고되기 전에 남은 줄을 발주하면, 예전부터 있던 문제
       (분할 발주에서 입고 대기 건의 발주번호가 어긋나 붙음) 때문에 입고 창의 발주처·수량이 서로 바뀌어 보일 수 있음.
       먼저 발주한 것을 입고처리한 뒤에 남은 줄을 발주하면 맞게 붙음
   · (v2.4.15) 발주 줄의 납품처는 늘 수주를 따라감 (수주관리 [수정]으로 납품처를 바꾸면 발주 줄에도 반영 — 지금까지는 예전 납품처가 남았음).
     발주 줄의 수량·납기일·발주처는 수주에서 그 값을 바꿀 때만 수주를 따라 바뀜 (품명을 바꾸면 발주처도 새 품목의 발주처로).
     발주관리 [수정]에서 따로 고친 값이, 수주의 다른 칸만 고쳤는데 수주 값으로 되돌아가지 않게 하기 위함 — 값이 원래 수주와 같던 줄은 예전과 결과가 같음
   · (v2.4.15) [납기일·납품처 변경] 창: 납기일은 창에서 날짜를 바꿨을 때만 수주·발주 줄에 반영 (납품처만 바꾸면 납기일은 건드리지 않음).
     발주관리의 줄에서 열면 그 줄의 납기일이 보임 — 수주와 다르면 안내가 나오고, 날짜를 바꿔 저장하면 수주·다른 발주 줄·입고예정도 그 날짜로 바뀜
     (그 줄의 납기일이 비어 있으면 수주의 날짜가 채워져 있고, 그대로 저장하면 그 줄에 들어감).
     수주관리에서 열었을 때 납기일이 수주와 다른 발주 줄이 있으면 안내가 나옴 — 그런 줄은 날짜를 바꿔 저장할 때만 함께 바뀜.
     저장 뒤 안내의 [🖨 발주서 재출력]은 이번에 실제로 바뀐 발주 줄의 발주서를 엶 (분할 발주에서 바뀌지 않은 앞 번호가 열리던 것)
   · (v2.4.15) 발주취소(선택 취소 포함): 취소한 수량은 예전처럼 같은 수주의 미발주 줄 하나로 합쳐지는데, 합쳐지는 줄들의 납기일·발주처가 서로 다르면 확인 창에서 알려줌
     (합친 줄에는 한 가지 납기일·발주처만 남음 — 분할 발주 뒤 남은 줄만 [수정]으로 바꿔 둔 경우. 다시 발주하기 전에 발주관리에서 확인)
   · (v2.4.15) 데이터 검진 "발주완료인데 입고 대기 레코드 없음"의 [미입고 생성]: 일부가 이미 입고된 건은 남은 수량만 만듦 (예전에는 발주수량 전체를 다시 만들었음).
     발주관리 [수정]에서 수량을 수주보다 많게 고쳐 발주하고 수주수량만 입고하면 이 항목이 나올 수 있음 — 더 들어올 것이 있으면 [미입고 생성], 없으면 그대로 두면 됨
